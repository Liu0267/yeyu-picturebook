# 《页语》开发者A执行手册
## 纸质绘本内容理解、可信视频生成与生成链路编排

**角色定位：内容理解与可信视频生成负责人**  
**实施优先级：P0完整闭环 → P1质量优化 → P2可选创新**  
**协作对象：开发者B（智能伴读、前端及系统集成）**

---

## 一、项目目标与职责边界

### 1.1 核心目标

独立建成一套真实、可靠、可追溯的离线生成流水线：

**授权纸质绘本 → 书页采集 → OCR与VLM理解 → 角色和事件事实表 → 原作约束的故事与分镜 → 真实AI视频生成 → 语音字幕合成 → 成片质量检查 → 实际视频帧证据 → 发布给B调用。**

最终要求：B无需理解内部视频模型的实现，即可通过约定接口获取书页事实、合格成片、实际视频帧及其时间标识。

### 1.2 你的责任

- 对原书图文理解的可核查性负责。
- 对原作核心人物、剧情和画风的一致性负责。
- 对真正调用视频生成服务并形成可播放视频负责。
- 对生成任务的状态、失败恢复、资源用量和可复现记录负责。
- 对交付给B的数据结构、版本和真实性负责。

### 1.3 不属于你的工作

B负责前端业务页面、视频播放器、实时ASR、随机问答、视频检索、触控交互及会话状态。A不另行开发这些功能，只提供生成过程所必需的接口、模型适配器和测试数据。

## 三、实施任务包

### A01：建立项目基础架构和共同数据协议（P0）

**开始条件：立即执行，不等待真实授权数据。**

具体任务：

1. 与B共同确定仓库、Python及前端运行版本、模型调用方式、目录结构和接口前缀。
2. 在 `shared/schemas/` 中定义 `BookManifest`、`ClipAsset`、`FrameEvidence`、`RunRecord`。
3. 用Pydantic定义服务端Schema，生成OpenAPI文档，提供给B生成TypeScript类型。
4. 创建完全人工构造的Mock书页、事实、视频记录和图片。
5. 定义统一错误码、运行状态、版本号与异步任务协议。
6. 配置环境变量、依赖锁定、基础日志与模型密钥管理。

**必须输出：**

- `shared/schemas/`
- `shared/contracts/openapi.json`
- `shared/fixtures/mock_book.json`
- `generation/app.py`
- `.env.example`
- `README_generation.md`

**完成标准：** B可以不启动真实OCR或视频模型，仅通过Mock API完成文件解析、书页展示、生成进度及视频列表加载。

### A02：纸页采集、图像预处理与OCR（P0）

**输入：** 具有明确赛事授权的纸页图像及其来源记录。

实现内容：

- 支持单页或多页图像输入，记录书籍ID、扫描序号和印刷页码。
- 原始图片不可覆盖，预处理生成独立文件。
- OpenCV完成旋转、裁切、透视矫正及基本质量检测。
- 检测模糊、反光、遮挡、缺页、重复页及页序异常。
- PaddleOCR作为候选OCR实现，保留每条文字的文本、边界框、置信度及读取顺序。
- 艺术字、严重低置信度区域可交VLM辅助复核。
- 保存OCR原始值、模型建议修正值和人工最终确认值，不静默覆盖识别结果。
- 向B提供页面校对所需的读取和写入接口。

**输出文件：**

- `pages/raw/`
- `pages/rectified/`
- `pages/ocr.json`
- `pages/quality_report.json`

**验收：** 用授权样本抽查识别正确性；人为制造模糊、倾斜、反光图片，系统能够拒绝或提示复核，不能编造看不清的原文。

### A03：VLM页面理解、角色表和事件表（P0）

实现内容：

- 同时读取原始插图、OCR文字、图文区域及必要的相邻页信息。
- 抽取角色、物品、场景、动作、情绪和事件。
- 建立全书统一的 `entity_id` 与 `event_id`，避免跨页同一角色产生不同身份。
- 为关键角色保存获准使用的原页参考裁片及外观描述。
- 事实必须带来源，例如原书文字区域、原书图片区域。
- 将视觉推断与原书明示事实分开。
- 对否定句、数量、人物关系、道具归属和事件先后进行重点检查。
- 保留VLM原始输出、Schema校验结果及人工修订历史。
- 允许B使用校对界面修改文字、角色、事实，修改后增加版本号。

**交付物：** `manifest.json`、`entities.json`、`events.json`、角色参考图和证据记录。

**验收：** 随机选择角色及事实，能够追溯至原书对应页和原始区域；跨页角色标识一致；事实不能无来源地自动进入最终确认状态。

### A04：原作约束的故事、分镜及风格锚定（P0）

这是生成质量的核心环节。

具体实现：

1. 以确认后的原书事实和事件顺序生成适合讲述的旁白。
2. 分别保存原文、旁白和新增解释，不将创作性补充写回原书事实。
3. 将故事拆分为可执行的 `ShotSpec`，每个镜头绑定原页、角色、事件及参考图片。
4. 建立全书角色设定和画风描述，保留色彩、笔触、构图等风格信息。
5. 优先使用当前原书页及固定角色参考，避免只依赖上一张生成图片。
6. 限制无依据的新增角色、动作、物品和情节转折。
7. 根据镜头生成后续视频模型可调用的提示词和参数。
8. 引入基本事实校验；不通过的分镜定向修改，而不是无差别重新生成整本书。

**交付物：** `storyboard.json`、`style_profile.json`、`shot_specs.json`、提示词版本文件。

**验收：** 每个镜头都能追溯到原页；评测人员可以说明该镜头表现了原书什么内容，有哪些必要的演绎。

### A05：真实AI视频生成与资产管理（P0）

**不得将静态图片推拉、幻灯片或预存演示视频冒充文生视频生成结果。**

具体实现：

- 对接一条实际可用且允许处理赛事素材的视频生成模型路线。
- 为视频服务编写独立适配器，隔离模型名、参数和供应商API。
- 支持异步提交、任务查询、下载、超时与失败重试。
- 每项生成任务包含 `run_id`、`shot_id`、输入版本、模型版本及配置哈希。
- 记录真实调用ID、开始结束时间、费用/用量及生成状态。
- 保留有限重试，避免视频任务重复提交造成超额消耗。
- 对已通过审核的其他片段进行复用，不因单页失败重新生成整本书。
- 输出每页或每镜头真实MP4，并保存原始媒体元数据。
- 视频资源使用受控资产ID和版本，不向B暴露服务器绝对路径。

**完成标准：** 从授权输入发起一项新的视频生成任务，能够在日志中找到完整调用、返回结果和可播放的真实输出。失败时显示失败，不能伪报全部成功。

### A06：旁白、TTS、字幕与音画同步（P0）

实现内容：

- 根据原书事实确定旁白内容。
- 对接获准使用的TTS服务，保存真实音频文件和格式。
- 根据真实音频时长安排片段和字幕，必要时进行句子级对齐。
- 使用FFmpeg进行必要的音画合成及媒体标准化。
- 配乐和音效必须有来源记录，优先保证语音清楚。
- 区分旁白、角色语言、伴读解释，不混用事实来源。
- 支持局部重新合成，不改变未经修改的视频资产。
- 输出可播放的单段和连续阅读视频及相关时间信息。

**交付物：** `audio/`、`subtitles/`、`clips/`、`clip_manifest.json`。

**验收：** 无旁白截断、明显字幕错位、视频时长不一致或因音效覆盖语音的问题；B能够通过标准视频播放器直接播放。

### A07：真实成片复核、抽帧与证据发布（P0）

这是与B进行实质交接的关键任务。

具体实现：

1. 对真实生成的视频按镜头边界和关键事件抽取实际帧。
2. 保存帧的真实视频ID、版本、时间码和受控资产引用。
3. 使用VLM或人工复核形成实际可见物体、角色、动作和事件描述。
4. 画面描述必须来自实际成片，而非未经检查的生成提示词。
5. 分别保存原书事实和视频实际画面事实；冲突时保留双方证据。
6. 检查人物身份、角色数量、关键物品、剧情顺序、画风和内容安全。
7. 不合格片段进入 `needs_review` 或 `failed`，不能自动发布。
8. 合格片段生成 `approved` 状态并向B发布 `ClipAsset` 与 `FrameEvidence`。
9. 为B提供可进行语义检索和动态点选的数据基础。

**交付物：**

- `frame_evidence.json`
- `frames/`
- `quality_report.json`
- `approved_clips.json`

**验收：** B随机抽取某一时间码，A的证据帧与实际播放视频一致；修改视频后旧帧数据自动失效。

### A08：显式多Agent工作流与可靠性（P0）

不必设计十几个独立大模型Agent，而应围绕职责划分必要的工作节点。

建议节点：

`Ingest → OCR → PageUnderstanding → Storyboard → VideoGeneration → TTS/Render → FrameValidation → HumanReview → Publish`

要求：

- 每个节点具有明确输入、输出、版本和执行条件。
- 任务状态包括排队、运行、待审核、成功、失败、取消、过期。
- 任务支持断点恢复、有限重试、超时、取消和局部重跑。
- 所有关键生成保存输入哈希、提示词版本、模型/接口版本、参数、结果资产哈希和调用日志。
- 优先保障交互请求资源，不允许视频生成任务无限占用全部算力。
- 能通过日志定位指定视频片段对应的输入和调用。
- 对随机模型区分“原产物可校验”“配置可重跑”和“输出逐像素一致”；不要对后者作不切实际的保证。

**验收：** 人为让某页视频生成失败、重启服务后能够只恢复对应任务；B已经加载的其他合格视频不受影响。

### A09：生成质量验证、消融与交付说明（P0/P1）

需要建立的测试：

- 原文OCR准确率与低置信区域分布。
- 角色身份和剧情事实抽查。
- 原书与实际视频盲评，包括画风、角色、情节、连贯性。
- 成片失败率、重试次数、实际生成耗时及成本。
- 分镜约束开启与关闭的同条件对比。
- 实际成片复核能否发现并拦截错误。
- 模型错误、API超时、版本修改后的恢复测试。

所有结果必须提供样本数、测试条件、统计方式和原始记录，不得把预设目标写成已达到的成绩。

**P1强化：** 若P0稳定且确有测试收益，再加入风格指纹、自动冲突定位、角色外观漂移比较和更细粒度的局部重生成。

## 四、与B完全一致的数据及接口合同

### 4.1 必须提供的四种核心对象

| 对象 | 主要字段 | 说明 |
|---|---|---|
| `BookManifest` | `book_id`、`page_id`、`page_revision`、`facts`、`entities`、`source_refs` | 可信原书内容 |
| `ClipAsset` | `clip_id`、`page_id`、`asset_version`、`duration_ms`、`status`、`asset_id` | 已生成视频资产 |
| `FrameEvidence` | `frame_id`、`clip_id`、`asset_version`、`t_ms`、`visual_claims` | 实际视频可见证据 |
| `RunRecord` | `run_id`、`step`、`model_version`、`input_hash`、`status`、`error` | 生成和复现记录 |

统一约定：

- ID在服务端生成；书、页、角色、镜头及片段分别使用稳定ID。
- 时间统一为毫秒；坐标统一为实际视频内容范围内的0—1归一化坐标。
- 原书事实和实际视频内容不得互相覆盖。
- 任何新视频版本必须令旧成片索引和触控缓存失效。
- 所有资产以ID访问，不暴露内部路径。
- Mock数据带明确的 `is_mock` 标识，不进入正式评测及演示成绩。

### 4.2 A负责提供的核心接口

| API | 最低交付要求 |
|---|---|
| `POST /v1/books` | 建立书籍及导入任务 |
| `GET /v1/books/{book_id}/manifest` | 返回版本化原书事实 |
| `PATCH /v1/pages/{page_id}/review` | 保存人工校对，检查期望版本 |
| `POST /v1/clips` | 提交生成任务并返回 `run_id` |
| `GET /v1/runs/{run_id}` | 查询真实任务状态与可重试错误 |
| `GET /v1/books/{book_id}/clips` | 返回合格片段及视频证据 |
| `GET /v1/assets/{asset_id}` | 依据权限返回媒体资源 |

所有API统一采用 `request_id / status / data / error / warnings`。异步任务返回202和任务ID；版本冲突返回409；错误提供 `code`、`message` 和 `retryable`。任务进度可使用SSE推送，B可以同时用查询接口兜底。

### 关键并行原则

M0后，A无需等待B写完页面就可以运行生成工作流；B也无需等待A生成全部视频才开始做交互。

A应尽早向B提供一段可播放的真实成片及其证据，不要到整本书全部生成后才第一次交接。

## 六、A的独立测试清单

正式提交前逐项确认：

- [ ] 能从真实获授权书页运行OCR与VLM。
- [ ] 原始输入、识别结果和人工修订分开保存。
- [ ] 角色及事件具备稳定ID和原书依据。
- [ ] 故事及分镜不擅自改变关键情节。
- [ ] 实际调用视频生成服务并记录调用信息。
- [ ] 视频、语音和字幕可以完整播放。
- [ ] 失败视频不会被标记为全部成功。
- [ ] 视频抽帧对应真实文件和真实时间码。
- [ ] 片段有明确版本、审核状态与可回溯来源。
- [ ] 重生成后旧帧和旧索引能够失效。
- [ ] 并发、重试、超时和取消具有明确行为。
- [ ] 不会跨书籍、跨会话混用资源。
- [ ] 能提供质量统计、失败案例和复现说明。
- [ ] 模型、数据、代码及素材来源和授权可查。
- [ ] B能在不修改A内部代码的情况下接入视频资产。

## 七、异常与阻塞处理

| 风险 | 处理方式 |
|---|---|
| 授权数据尚未开放 | 使用明确标识的合成Mock验证协议及工程框架，不擅自上传其他绘本 |
| 视频API无法调用 | B继续使用Mock，A并行验证替代模型；真实视频任务标为未完成 |
| 视频生成过慢 | 缩小最小测试闭环、减少不必要的镜头、合理并行；完整范围仍须后续验收 |
| 角色或风格漂移 | 强化原书页与角色参考、缩小镜头运动、局部重生成 |
| OCR错误引起剧情错误 | 回到原始书页校对，不让下游继续消费错误版本 |
| API调用过量 | 幂等控制、并发上限、费用配额和有限重试 |
| 成片与原文冲突 | 分开记录原书事实与视频内容，阻止问题片段发布并局部修复 |
| B发现数据格式不兼容 | 先提交协议变更和兼容测试，再修改实际实现 |

## 八、最终交付与签收

A最终需要将以下内容正式交给B：

**代码包：** 生成服务、依赖文件、模型适配器、配置样例、启动和复现脚本。

**内容包：** 原书理解结构、真实生成片段、音频字幕、实际帧证据、角色和事件表。

**证据包：** 完整模型调用记录、生成质量检查、版本关系、盲评及失败记录。

**文档包：** 生成架构图、关键实现说明、模型与素材来源、性能测量口径、已知局限。

**最终签收标准：** B使用约定接口，不修改A的内部实现，能够导入书页、获取原书事实、查询生成进度、播放实际视频并读取其证据。随后A应反向验收B的随机问答结果，核查回答所引用的原书与视频依据是否真实。
