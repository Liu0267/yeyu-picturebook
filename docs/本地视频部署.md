# 本地图生视频部署

本路线把书页裁片交给本机Wan2.2模型，不调用视频云API。VLM与TTS继续使用各自独立的MLX环境；视频程序使用stable-diffusion.cpp和Metal。当前固定版本已完成512×384、33帧完整片段及真实配音合成，结果见《本地真实视频验收》；单次生成约30分钟，动作幅度很小。

本机环境为Apple M4、16GB统一内存、macOS 27.3。其他机型尚未实测；这里不承诺实时生成。程序只在一个工作进程中顺序处理生成任务。

## 安装本地运行程序

需要Xcode命令行工具、Python 3.12、Git及FFmpeg/FFprobe。在项目根目录执行：

```sh
mkdir -p .local
python3.12 -m venv .local/video-tools
.local/video-tools/bin/python -m pip install -r requirements.video-tools.lock.txt
git clone --no-checkout https://github.com/leejet/stable-diffusion.cpp.git .local/stable-diffusion.cpp
git -C .local/stable-diffusion.cpp checkout 77b72a2efed78f55de26892c7e909cee001e8b83
git -C .local/stable-diffusion.cpp submodule update --init ggml
.local/video-tools/bin/cmake -S .local/stable-diffusion.cpp -B .local/stable-diffusion.cpp/build -DSD_METAL=ON -DSD_WEBP=OFF -DSD_WEBM=OFF -DCMAKE_BUILD_TYPE=Release
.local/video-tools/bin/cmake --build .local/stable-diffusion.cpp/build --target sd-cli -j 2
```

这里保留已做过本机预检的固定版本。当前主分支小尺寸测试曾出现严重条纹，不能只因程序退出0就认为画面正确；需要看实际输出。

## 下载固定权重

```sh
.local/video-tools/bin/python scripts/download_wan_models.py --directory .local/Wan2.2-TI2V-5B-GGUF
```

最终所需组件约6.8GB：Q4_K_S主模型、Q4_K_M文本编码器与约23MB的TAEHV编解码器。脚本依据`docs/wan_model_manifest.json`中的固定revision和SHA256下载并核验，不读取书籍或密钥。原始大VAE只用于前期对照，最终配置不要求下载它。

## 启用本地供应商

在私有`.local/runtime.env`中设置以下绝对路径：

```sh
export YU_VIDEO_PROVIDER=wan_local
export YU_WAN_EXECUTABLE=/你的路径/.local/stable-diffusion.cpp/build/bin/sd-cli
export YU_WAN_MODEL_DIR=/你的路径/.local/Wan2.2-TI2V-5B-GGUF
```

双击`启动本地服务.command`。书页、分镜审核及`POST /v1/clips`调用方式不变。只有显式声明为本地的供应商跳过外传许可；未知供应商仍受原授权门禁约束。没有本地程序或权重时返回明确配置错误。

当前实测配置把裁片缩放为512×384，按8fps和`4n+1`帧生成；4秒分镜对应33帧，实际约4.125秒。它不是原生720P或24fps输出。API保存实际时长、输入PNG/裁片哈希、程序哈希及日志；帧证据按实际PTS提取。TTS较长时，补足最后一帧并记录补尾时长，补尾不算新增AI动态。

本地`model_call_id`使用对应run_id，用于追溯日志，并非云平台任务ID。新视频默认待审核；通过实际帧审核后才会进入默认片段列表。本路线没有实现B方业务播放器、问答或实时ASR。

主模型及文本编码器来源为Apache 2.0模型卡；TAEHV和原生运行程序为MIT。权重、原生程序和私有配置不随代码包分发。详细来源、固定revision和哈希见模型清单，接口联调见《B方联调说明》。
